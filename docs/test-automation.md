# 测试自动化：注入输入与截图

这是调试期间用的工具，面向**给卡带做回归测试**的场景：注入按键、模拟触摸、
截图比对。

普通的游玩和调试用不到这一页，README 里只留了一行指引。

## 前提

必须先有一个活动调试会话。这些命令都通过活动的调试会话发送，**不要**自己
开第二条到 3563 的连接 —— 模拟器的调试通道只允许一个客户端，第二条会挤掉
扩展自己的那条，表现就像插件坏了。

## 两个入口

同一批命令有两个入口，行为完全一样：

1. **命令面板**：`CLX Test` 分类下的五条命令（仅调试期间可见）
2. **调试控制台**：以 `!` 为前缀（适合一帧一帧地试）

`!` 前缀是控制台的逃生口：带 `!` 的输入走测试自动化，其余输入原样转发给模拟器。
两者都不解释内容 —— 你在 REPL 里敲的就是模拟器命令。

## 命令

| 命令面板 | 调试控制台 | 作用 |
|---|---|---|
| **CLX Test: Inject Buttons** | `!btn <键位…> <时长>` | 按住 CLX 键位；不带参数是查询当前按键状态 |
| **CLX Test: Hold a Key** | `!key <键名> <时长>` | 按住键盘某键（命令面板里固定 500ms） |
| **CLX Test: Move or Touch** | `!mouse <x> <y>` | 设置鼠标/触摸位置，坐标是卡带 VM 坐标系 |
| **CLX Test: Screenshot** | `!shot` | 存一张 BMP 并打印像素 md5 |
| **CLX Test: Show Input State** | `!input?` | 打印帧号、按键、鼠标、键盘和各手柄 |

「持续按住」的停止方式各有一个常量：`btn 0`、`key 0`、`mouse 0`。

### 时长的三种写法

`btn` 与 `key` 都接受三种形式：

| 写法 | 含义 |
|---|---|
| `1` | 一帧 |
| `30` | 30 帧 |
| `500ms` | 500 毫秒 |
| `0` | 松开（等价于立即释放） |

## 例子

```
!btn LEFT 1          LEFT 一帧
!btn LEFT A 30       LEFT + A 按住 30 帧
!btn LEFT 500ms      LEFT 按住 500 毫秒
!btn 0               松开
!shot                截图并打印像素 md5
!input?              当前输入状态全貌
```

键位名**不做白名单校验**：官方会加新键位，硬编码列表只会挡住合法的。键名
大小写不敏感，会去重。

## 截图

截图写在 `globalStorageUri/screenshots/`，**不会**落到你的源码旁边。

这一点是刻意设计：模拟器的工作目录是卡带所在目录，如果用它的默认路径，
BMP 会撒在源码目录里。

返回的 `md5` **只覆盖像素数据**，所以：

- 跨平台一致（不掺文件头、时间戳）
- 可以当金图比对的键

**不做**金图比对本身 —— 只报 md5，比对由调用方自己决定怎么做。

## 实现位置

想改这些命令时看这里：

| 文件 | 职责 |
|---|---|
| `src/debug/testAutomation.ts` | 应答解析与命令构造（纯逻辑，不 import vscode，有测试） |
| `src/debug/testAutomationCommands.ts` | 命令面板 adapter |
| `src/debug/debugSession.ts` | 调试会话里 `clx.testAutomation` 自定义请求的入口 |
| `test/testAutomation.test.ts` | 上面那个纯逻辑的用例 |

截图路径由调试适配器定向到 `globalStorageUri/screenshots/`，不要改成让模拟器
自己决定。

## 为什么不做成"直连模拟器"

看起来直接连 3563 更简单，但单客户端限制会让这么做变成破坏性操作：你连上去，
扩展的调试连接就被踢掉了。所以全部走活动会话的 `clx.testAutomation` 请求。

同理，`yarn e2e` 也遵守这条 —— 它通过 `session.customRequest('clx.testAutomation', …)`
调用。
